Extension points for Products with their own Einladung, roles and user fields. `authSchema({ einladung })`: a Product's own columns on `einladung` (`AuthSchema<A, M, U, E>`, the row type `EinladungRow<typeof schema>`, never the token's hash); `einladungRepo` selects every column, `einladungService(ctx).erstellen(userId, { email, ...extras })` writes them, `pruefen` returns them, `annehmen` returns the row and runs the hook, `einladungLoad` and `signupLoad` put them into the page data's `einladung`. `createAuth({ hooks: { beforeUserCreate, afterUserCreate, afterEinladungAccepted, beforeUserDelete } })`: at signup the Einladung is accepted first, then the admin role given, then `afterUserCreate` runs; `afterEinladungAccepted` also runs when a logged-in user accepts; `beforeUserDelete` runs in `userRepo.kontoLoeschen`. `createAuth({ einladung: { input, authorize } })`: `createEinladung` takes keys beyond `email`, parsed by `input` (none allowed without it, a 400) and refused by `authorize` with a message (a 403, may be async); the result keeps them. `createAuth({ roles })` (default `["admin", "user"]`): `setUserRole` checks against it, `manageUserLoad` adds `roles`, `AdminView` renders its select from it with `roleLabel`. `AdminView` props `intro`, `showEinladungErstellen`, snippets `userExtra(user, isSelf)`, `einladungExtra(einladung)`, `einladungFields(extras)` (also on `SettingsPage`, reaching the Invitations tab; `EinladungErstellen` sends `{ email, ...extras }`); a banned account shows "(banned)"/"(gesperrt)". `userRepo.setBanned(userId, banned, reason?)` bans (ending the sessions) or unbans. Profile fields: `SettingsPage` snippet `fields(extra)` inside the name and email form, `homeLayoutLoad` adds `userFields`, `updateUserProfile` takes the extra keys (declared in `userFields`, coerced to the field's type, else a 400) into `auth.api.updateUser`. `setAuthUi({ authClient, displayName })` names a person in the settings header, the mobile menu and the admin's list. `SettingsTabDef.after` places a tab; `SettingsPage` props `invitations` and `menuFooter`. `RegisterForm` props `redirectTo` and `description`; `EinladungPage` props `title` and `loggedIn(einladung)`. Social login errors land on `/auth/login`. `createUser(ctx, email, name)` takes a name. New messages: `unknownRole`, `einladungUnknownFields`, `einladungInvalidFields`, `unknownField`, `bannedMark`, `roleAdmin`, `roleUser`.
